==================================================
2. TARGET FORMAT
==================================================

The target format is a compact JSON-like structured text representation.

For an object such as:

control:
  description: control
  required: true
  properties:
    brandIdentifier:
      description: brandIdentifier
      type: string
      required: false
    businessSourceCode:
      description: businessSourceCode
      type: string
      required: false

convert it to:

{
  "control(control,true)": {
    "brandIdentifier(brandIdentifier,false)": "string",
    "businessSourceCode(businessSourceCode,false)": "string"
  }
}

The syntax means:

OBJECT:

"FIELD_OR_NODE_NAME(DESCRIPTION,REQUIRED)": {
    child nodes
}

LEAF FIELD:

"FIELD_NAME(DESCRIPTION,REQUIRED)": "TYPE"

==================================================
3. MEANING OF EACH PART
==================================================

For:

"brandIdentifier(brandIdentifier,false)": "string"

the parts are:

Field name:
brandIdentifier

Description:
brandIdentifier

Required:
false

Datatype:
string

For:

"control(control,true)": {

the parts are:

Object/array name:
control

Description:
control

Required:
true

The contents inside `{ }` are its child properties.

==================================================
4. DESCRIPTION HANDLING
==================================================

The description must be copied exactly from the RAML.

DO NOT rewrite, shorten, summarize, correct, normalize or paraphrase descriptions.

If the RAML contains:

description: brandIdentifier

output:

"brandIdentifier(brandIdentifier,false)": "string"

If the RAML contains a longer description such as:

description: cacheID, applicable during requotes and mid term adjustments. Originally returned in quote response

output the complete description exactly:

"cacheID(cacheID, applicable during requotes and mid term adjustments. Originally returned in quote response,false)": "string"

IMPORTANT:

A description may itself contain commas.

Therefore, DO NOT interpret the first comma inside the description as the separator between description and required.

The final `,true)` or `,false)` identifies the required value.

Do not remove commas from descriptions.

==================================================
5. MISSING DESCRIPTION
==================================================

If a RAML field/property has NO `description`, explicitly use:

Not Present

Example:

RAML:

someField:
  type: string
  required: false

Output:

"someField(Not Present,false)": "string"

Do NOT leave the description blank.

Do NOT invent a description from the field name.

Do NOT use the field name as the description when the description is absent.

Use exactly:

Not Present

==================================================
6. MISSING REQUIRED VALUE
==================================================

If `required` is not present in the RAML:

use:

Not Present

Example:

"someField(someField,Not Present)": "string"

Do NOT assume that missing `required` means false.

Do NOT convert missing into Optional.

==================================================
7. MISSING TYPE
==================================================

If a leaf property does not explicitly contain a datatype:

use:

"fieldName(description,required)": "Not Present"

Do NOT infer the datatype from the field name or description.

==================================================
8. OBJECTS / CONTAINERS
==================================================

If a node contains child properties, represent it as an object/container using `{ }`.

Example RAML:

customer:
  description: customer
  required: true
  properties:
    customerId:
      description: customerId
      type: string
      required: true
    customerName:
      description: customerName
      type: string
      required: false

Output:

{
  "customer(customer,true)": {
    "customerId(customerId,true)": "string",
    "customerName(customerName,false)": "string"
  }
}

Do not convert the object itself into a leaf field.

==================================================
9. ARRAYS
==================================================

Arrays must be preserved as arrays and their child properties must remain inside the array structure.

For example, if RAML contains:

drivers:
  type: array
  description: drivers
  required: false
  items:
    type: object
    properties:
      driverName:
        description: driverName
        type: string
        required: false
      driverAge:
        description: driverAge
        type: integer
        required: false

represent the array as:

{
  "drivers(drivers,false)[array]": {
    "driverName(driverName,false)": "string",
    "driverAge(driverAge,false)": "integer"
  }
}

The `[array]` marker is mandatory for an array node so that the downstream validator can distinguish an object from an array.

Do not remove the array information.

For nested arrays, preserve every array level.

Example:

{
  "drivers(drivers,false)[array]": {
    "vehicles(vehicles,false)[array]": {
      "registrationNumber(registrationNumber,false)": "string"
    }
  }
}

==================================================
10. ARRAY ITEM OBJECTS
==================================================

If an array's `items` contains an object, do NOT create an unnecessary separate field called `items`.

The array name itself represents the array and its child properties should be placed inside it.

Correct:

    "passengerAge(passengerAge,false)": "integer"
  }
}

  }

Do not expose `items` as a business field.
